1. No empieces por el algoritmo. Empieza por la necesidad.

Una idea atractiva no siempre es un problema bien definido. Antes de buscar bibliotecas, aclara quién tiene la necesidad, qué información existe y qué resultado sería útil.

Plantilla para convertir una idea en problemaCuando [situación concreta], [persona o comunidad] necesita [resultado útil], porque [consecuencia o dificultad actual].
IDEA VAGA

“Quiero hacer una IA para ayudar a los alumnos.”

No explica qué dificultad atenderá, con qué información trabajará ni qué hará el sistema.

PROPUESTA MÁS CLARA

“Quiero organizar comentarios anónimos sobre servicios escolares.”

El sistema clasificará cada comentario por tema —limpieza, atención o alimentos— para que el comité identifique los asuntos más mencionados.

Regla de oro: si el alumno no puede explicar el problema sin decir “una IA que haga todo”, todavía necesita delimitarlo. El proyecto debe resolver una tarea concreta y comprobable.

2. Explorador: ¿qué ruta tecnológica tiene sentido?

Selecciona las características de tu problema. La orientación es una primera hipótesis: el equipo debe comprobarla con ejemplos y datos reales o autorizados.

Tu orientación aparecerá aquí.

Prueba, por ejemplo, texto + categoría + sí tengo etiquetas para explorar un clasificador de comentarios.

PROGRAMACIÓN TRADICIONAL

Reglas conocidas

Cuando las condiciones son claras y están definidas por una persona, un programa con if, funciones y ciclos puede ser suficiente.

Ejemplo: avisar si una fecha de entrega ya venció.

MACHINE LEARNING

Aprender patrones de datos

Se entrena un modelo para clasificar, estimar o agrupar ejemplos. No basta con decir “quiero predicciones”: se requieren datos adecuados.

Ejemplo: estimar la demanda de préstamo de libros.

PNL / VISIÓN

Tipo de información

PNL trabaja con lenguaje humano; visión artificial trabaja con imágenes y video. Pueden usar ML, reglas o redes neuronales.

Ejemplo: clasificar comentarios / identificar objetos.

3. Algoritmos: etiquetados y no etiquetados

La pregunta clave es: ¿en los ejemplos históricos ya sabemos cuál era la respuesta correcta? Si sí, tenemos etiquetas para aprendizaje supervisado. Si no, podemos explorar estructura con métodos no supervisados.

4. ¿Cuándo es ML, PNL o visión artificial?

No son tres nombres para lo mismo. Machine Learning es una familia de métodos para aprender patrones desde datos. PNL y visión artificial se refieren al tipo de información y tareas que se procesan. Pueden combinarse.

MACHINE LEARNING

Datos en forma de variables

Tablas con números y categorías para descubrir relaciones, clasificar o estimar.

Entradas: columnas como fecha, cantidad, temperatura, uso.

Salida: categoría, estimación o grupo.

PNL · LENGUAJE

Palabras, frases y documentos

Permite procesar texto humano: separar tokens, quitar ruido, convertir texto en vectores, clasificar opiniones o recuperar información.

Entradas: comentarios, preguntas, documentos.

Salida: tema, sentimiento, intención o términos relevantes.

VISIÓN ARTIFICIAL

Imágenes y video

Analiza pixeles para clasificar imágenes, detectar objetos, localizar regiones o seguir movimiento.

Entradas: fotografías, cuadros de video.

Salida: clase, objeto o ubicación.

Se presenta como panorama, no como eje obligatorio del módulo.

Idea importante para M2S2: PNL no significa automáticamente Machine Learning. Tokenizar, contar palabras o buscar una expresión puede hacerse con reglas. Cuando usamos ejemplos etiquetados para que un modelo aprenda a clasificar texto, combinamos PNL + Machine Learning.

Ejemplo: PNL sin modelo ML

Buscar en un texto palabras como “horario”, “inscripción” o “constancia” con reglas o expresiones regulares. Sirve como primer prototipo, pero no comprende todas las formas de expresar una pregunta.

Ejemplo: PNL + ML

Reunir preguntas etiquetadas por intención —horarios, becas, inscripción—, convertirlas con TF-IDF y entrenar un clasificador. El modelo aprende patrones de ejemplos.

5. Diseñar un dataset que sí sirva

Un dataset es una colección organizada de ejemplos. Cada fila representa un caso y cada columna describe una característica o el resultado conocido.

TABULAR · SUPERVISADO

Objetivo: estimar cuántos préstamos habrá cada día.

TEXTO · SUPERVISADO

Clasificar comentarios

Objetivo: asignar un tema a cada comentario.

comentarioetiqueta

“Me atendieron rápido”atención
“El precio aumentó”precio

La columna etiqueta contiene la respuesta esperada.

Objetivo: descubrir agrupaciones sin decidir categorías antes.

comentario
“El patio está sucio”
“El baño requiere limpieza”
“El precio aumentó”

No existe columna de etiqueta. El equipo interpreta los grupos después.

Plantilla mínima para construir los datos

DecisiónPreguntas que debe contestar el equipo
Unidad de análisis¿Qué representa una fila: un comentario, un día, un equipo, una imagen?
Variables¿Qué columnas describen cada caso? ¿Son numéricas, categóricas, fecha o texto?
Objetivo / etiqueta¿Qué queremos predecir? ¿Quién asignó la etiqueta y con qué criterio?
Origen y permiso¿Los datos son propios, públicos, simulados o autorizados? ¿Se pueden usar?
Calidad¿Hay filas duplicadas, campos vacíos, etiquetas contradictorias o clases muy desbalanceadas?
Separación¿Cómo reservaremos ejemplos de prueba que el modelo no verá durante el entrenamiento?
Para una práctica escolar: comenzar con datos sintéticos o públicos y anónimos es válido para aprender el procedimiento. No subir nombres, teléfonos, matrículas, fotografías identificables, conversaciones privadas ni datos sensibles. Un dataset pequeño sirve para una demostración didáctica, pero no demuestra que el modelo sea confiable para uso real.

7. Dos proyectos ejemplo, desde la idea hasta la prueba

EJEMPLO A · PNL + ML SUPERVISADO

Organizador de comentarios escolares

1
Problema
Los comentarios sobre un servicio llegan mezclados y cuesta identificar los temas frecuentes.
2
Objetivo
Clasificar comentarios anónimos en categorías definidas: limpieza, atención, precio o calidad.
3
Dataset
Columnas: comentario y etiqueta. El equipo crea ejemplos ficticios o usa datos autorizados; define reglas claras para asignar cada etiqueta.
4
Ruta técnica
Revisar textos → normalizar lo necesario → TF-IDF → separar entrenamiento/prueba → entrenar un clasificador sencillo (por ejemplo, Regresión Logística o Naive Bayes) → evaluar.
5
Evaluación
Revisar matriz de confusión, precisión, recall y F1 por categoría. No quedarse solo con accuracy si las categorías tienen cantidades muy diferentes.
6
Demostración visual
Una persona escribe un comentario de prueba; la interfaz muestra la categoría predicha y una nota de que el resultado es una sugerencia, no una decisión oficial.
EJEMPLO B · ML SUPERVISADO TABULAR

Estimador didáctico de préstamos de biblioteca

1
Problema
La biblioteca quiere explorar si ciertos factores coinciden con días de más préstamos.
2
Objetivo
Estimar la cantidad de préstamos de un día a partir de variables sencillas.
3
Dataset
Columnas de entrada: día de la semana, si hay examen, actividad escolar y préstamos de días anteriores. Columna objetivo: prestamos.
4
Ruta técnica
pandas para DataFrame → exploración con gráficas → división entrenamiento/prueba → Regresión Lineal como primer modelo → comparar con un modelo de árbol.
5
Evaluación
Usar MAE y comparar el error con un método base sencillo. El resultado no es una certeza ni debe usarse para asignar recursos sin revisión.
6
Demostración visual
Un formulario permite elegir condiciones del día y presenta el número estimado, junto con una explicación de las variables utilizadas y las limitaciones.
Advertencia sobre datos pequeños: si el grupo inventa solo 10 o 15 filas, puede demostrar cómo funciona el flujo, pero no afirmar que descubrió un patrón confiable. Debe indicar que es un prototipo educativo y explicar qué datos necesitaría para mejorar.

Elementos que debe mostrar la interfaz

  1. Nombre del proyecto y problema concreto.
  2. Un campo para introducir el dato de prueba.
  3. Un botón claro para ejecutar la acción.
  4. Un resultado legible: categoría, estimación o grupo.
  5. Una explicación breve de qué significa el resultado.
  6. Limitaciones, fuente de datos y advertencia de uso responsable.

Herramienta visual sugerida

Gradio permite construir una interfaz web en Python alrededor de una función o modelo sin programar todo el frontend. Puede ejecutarse en notebooks y mostrar la demostración; para compartir mediante enlace público hay que evitar datos privados y revisar las condiciones del entorno.

Guía oficial de Gradio

1. Presentación

Problema, objetivo, beneficiarios, importancia y alcance.

2. Demostración

Interfaz que recibe un ejemplo y muestra la salida del sistema.

3. Evidencia técnica

Dataset, notebook, algoritmo, métricas, pruebas y limitaciones.

La interfaz no sustituye al modelo. Un formulario bonito que devuelve respuestas inventadas no es un proyecto de ML. La demostración debe llamar al proceso real que el equipo desarrolló y evaluó en Python.

9. Google Colab: el esqueleto técnico, no toda la exposición

El cuaderno de Colab funciona como bitácora técnica. Contiene las etapas en orden y espacios para que cada equipo complete su propio trabajo. La página visual sirve para que el público pruebe el prototipo.

Lo que debe mostrar Colab

  1. Problema y objetivo del equipo.
  2. Importación del dataset.
  3. Revisión de filas, columnas y tipos de datos.
  4. Preparación de variables y etiqueta (si aplica).
  5. Separación entrenamiento y prueba (si es supervisado).
  6. Transformación de datos o texto.
  7. Entrenamiento del algoritmo o agrupamiento.
  8. Evaluación e interpretación.
  9. Prueba con un caso nuevo.
  10. Conclusiones y limitaciones.

Lo que NO debe ser Colab

  • Una colección de celdas copiadas sin explicación.
  • Un modelo sin dataset identificable.
  • Una accuracy presentada como garantía.
  • Un proyecto donde el alumno no pueda explicar la etiqueta y el algoritmo.
  • La única interfaz que el visitante debe entender para conocer el proyecto.

10. Checklist de una propuesta que sí está lista para revisión

Antes de pedir autorización, el equipo debe poder contestar estas preguntas con frases concretas.

  • Puedo describir el problema en dos o tres oraciones.
  • Identifiqué quién se beneficiaría.
  • Mi objetivo se puede observar o medir.
  • Sé qué información recibirá el sistema.
  • Puedo explicar qué resultado entregará.
  • Sé si mi información es texto, tabla, imagen o una mezcla.
  • Sé si tengo etiquetas o no, y qué significan.
  • Tengo una idea inicial de cómo construir el dataset.
  • Puedo justificar por qué necesito ML, PNL, visión o reglas.
  • Reconozco los límites y riesgos de mi propuesta.
La pregunta que cada alumno debe poder responder¿Por qué elegí este algoritmo y estos datos para resolver este problema, y cómo demostraré que mi solución funciona?
